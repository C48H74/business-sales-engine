# Indecision and no-decision

Use when the buyer accepts the need but cannot choose. Distinguish indecision from poor value, polite refusal, priorities, budget and procurement. JOLT's four actions come from [S5](sources.md); questions and tests here are original adaptations. No-decision is not assumed to be every business's main loss cause.

| Action | Diagnose | Respond |
|---|---|---|
| Judge indecision | Wrong choice, missing information or implementation fear? | Name uncertainty tentatively; invite correction |
| Offer a recommendation | Which option fits confirmed requirements? | Recommend one path with tradeoffs/exclusions |
| Limit exploration | Which unanswered question could change the decision? | Agree bounded evidence and decision criteria |
| Take risk off the table | Which failure is unacceptable? | Feasible pilot, checkpoint, rollback or limited commitment |

Example: "It sounds like migration risk matters more than the feature list. Is that right? I recommend the smaller deployment first. We can test import accuracy and adoption before expanding. If those conditions fail, we stop under the pilot terms. Does that address it, or is something else unresolved?"

Bound exploration by agreement, not by suppressing due diligence or alternatives. Do not use urgency to counter fear of a wrong choice. Add an implementation owner and success/stop conditions; vague refunds may not solve operational risk.

Record uncertainty, resolving evidence, recommendation, residual risk and owner/date in the [mutual action plan](../templates/mutual-action-plan.md). Revise when new evidence changes fit. Respect deferral and refusal. See [objection library](../objections/library.md) for other diagnoses.
